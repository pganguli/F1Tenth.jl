API

The layers are the same as in the Python package: the gym environment, the simulator and its cars, and then the dynamics, collision and LiDAR models.

Environment

F1Tenth.F110Env — Type
F110Env(; seed=12345, map="vegas", map_ext=".png", params=VehicleParams(), num_agents=2,
          timestep=0.01, ego_idx=1, integrator=Integrator.RK4, lidar_dist=nothing, lidar_sweep=true)

The F1TENTH gym environment, with the keyword arguments of gym.make('f110_gym:f110-v0', **kwargs) in the Python code:

  • seed: the seed of the LiDAR noise
  • map: "berlin", "skirk", "levine", "vegas", a track from f1tenth_racetracks (for example "Austin" or "Spa"; Pkg downloads them when you use one for the first time; see F1Tenth.RACETRACKS), or the path of a map yaml file without its extension
  • map_ext: the extension of the map image, for example ".png" (the included maps use their own extension by default)
  • params: a VehicleParams, or a dict with all of its keys
  • num_agents: the number of cars
  • timestep: the physics time step in seconds
  • ego_idx: the index of the ego car (from 1)
  • integrator: Integrator.RK4 or Integrator.Euler
  • lidar_dist: the distance of the LiDAR in front of the center of gravity of the car, which is the point that the pose gives. (The docstring of the Python code says the rear axle, but its code also measures from the pose.) The default is params.lidar_x - params.lr, where NUC5 has the LiDAR (0.143 m).
  • lidar_sweep (not in the Python code): if true, take each LiDAR beam from the pose at the time of that beam in the sweep, as the real sensor does. If false, take the full scan from the pose at its first beam.

To operate the environment, use reset!, step! and render!.

F1Tenth.step! — Function
step!(sim::Simulator, control_inputs) -> Observation

Move all cars forward by one step. control_inputs is num_agents × 2: the requested steering angle in column 1, and the requested speed in column 2.

source
step!(env::F110Env, action) -> (obs, reward, done, info)

Move forward by one time step. action is num_agents × 2: the requested steering angle in column 1, and the requested speed in column 2.

  • reward is the time step.
  • done is true when the ego car crashes, or when all cars have done two laps.
  • info.checkpoint_done[i] is true when car i has done two laps.

The next call writes new values into the returned Observation and info.

F1Tenth.reset! — Function
reset!(car::RaceCar, pose)

Put the car at rest at pose = (x, y, θ). Reset its actuator chain, its clock and its collision flag, and start its scan noise again from seed. If the car has a map, it takes a first scan there. (The car does not move, thus the sweep has no effect.) The next sweep starts one scan period later.

source
reset!(sim::Simulator, poses)

Put car i at row i of poses (num_agents × 3: x, y, θ).

source
reset!(env::F110Env, poses) -> (obs, reward, done, info)

Start a new episode, with car i at row i of poses (num_agents × 3: x, y, θ). As in the Python code, the function does one step with zero input, and returns the result of that step.

F1Tenth.render! — Function
render!(env; mode=:human)

Draw the environment in a window (needs using GLMakie). Drag to pan, scroll to zoom.

  • :human shows the race in real time. Each frame waits until the wall clock is at the sim time. (Python only waits 5 ms for each frame.) If the drawing is more than 0.1 s late, or after a reset, the two clocks start again from the same time. The window does not try to catch up. The window draws a maximum of 60 frames for each second of sim time. If the last frame is more recent than that, render! does nothing and does not call the render callbacks. Thus a small timestep does not make the race slower than real time.
  • :human_fast draws a frame for each call and does not wait.

If you close the window, the next frame that render! draws causes an error.

F1Tenth.Observation — Type
Observation

The value that step! and reset! return. It has the entries of the observation dict of the Python code (ego_idx, scans, poses_x, poses_y, poses_theta, linear_vels_x, linear_vels_y, ang_vels_z, collisions, lap_times and lap_counts). To read them, use obs.poses_x, obs[:poses_x] or obs["poses_x"].

scan_times (not in the Python code) is the time from the reset to the first beam of the scan of each car in scans, as ROS gives the time of a scan.

The env uses the same arrays for all steps: each step writes new values into them. To keep the values of one step, use copy(obs).

Simulator(params, num_agents, seed; time_step=0.01, ego_idx=1,

F1Tenth.RaceCar — Type
RaceCar(params, seed; is_ego=false, time_step=0.01, num_beams=1081, fov=3π/2,
        integrator=Integrator.Euler, lidar_dist=params.lidar_x - params.lr, lidar_sweep=true)

One vehicle: the vehicle model, its low-level actuator chain (command limiter, steering servo and VESC speed loop; see F1Tenth.actuate!) and a LiDAR that scans at params.scan_rate.

  • With lidar_sweep, the car takes each beam from the pose at the time of that beam in the sweep, as the real sensor does. Without it, the car takes the full scan from the pose at its first beam.
  • state is (x, y, steer_angle, vel, yaw_angle, yaw_rate, slip_angle).
  • The scan noise comes from scan_rng. For scans with no noise, set it to nothing (as rng=None in the Python code).

The cars that a Simulator makes share its scan simulator and beam tables, as the class attributes of RaceCar in the Python code.

source
F1Tenth.body_hits_wall — Function
body_hits_wall(map, x, y, θ, length, width) -> Bool

True if a car body overlaps a wall cell of map (pixel value <= 128). The body is the length × width rectangle with its center at (x, y) and the heading θ. The test is exact for the grid: it compares the rectangle with the square of each wall cell near it. Cells that are not on the map are free.

F1Tenth.VehicleParams — Type
VehicleParams(; kwargs...)
VehicleParams(d::AbstractDict)

The parameters of one car: the vehicle model (see vehicle_dynamics_st) and its low-level actuator chain (see RaceCar). Each default is a published value for NUC5, the F1TENTH car of ForzaETH. Where ForzaETH publish no value, the default is a published default of the hardware of the car. Below, "race stack" is ForzaETH/race_stack, branch ros2-humble, which has the configuration of NUC5.

Tires (race stack, stack_master/config/NUC5/pacejka/dubi/default.yaml: the tire identification of NUC5 that ForzaETH did on their "dubi" floor, with friction_coeff: 1.0)

  • mu = 1.0: the friction scale on all tire forces. The value 1 is the identification floor.
  • Bf = 4.142, Cf = 0.4375, Df = 2.6476, Ef = 0.2332 and Br = 4.8721, Cr = 2.1651, Dr = 1.057, Er = 1.692: the front and rear Magic Formula coefficients. The lateral force on an axle is mu * D * Fz * sin(C * atan(B*α - E*(B*α - atan(B*α)))). Thus D is the maximum friction coefficient. The rear force has its peak at 1.00 times the load, at 0.25 rad of slip. Because Er > 1, the force then decreases, and it reverses after 0.63 rad. This is an artifact of the fit (at these angles the car already spins). The front force increases slowly: 0.45, 0.77 and 1.11 times the load at 0.1, 0.2 and 0.4 rad.

Body (race stack, stack_master/config/NUC5/car_model.yaml)

  • lf = 0.130, lr = 0.127: the distance from the center of gravity to the front and rear axles (m)
  • h = 0.074: the height of the center of gravity (m)
  • m = 2.783: the mass (kg)
  • I = 0.0627: the yaw moment of inertia (kg m²)

Steering hardware (race stack, stack_master/config/NUC5/car_model.yaml)

  • s_min = -0.4189, s_max = 0.4189: the mechanical limits of the steering angle (rad)
  • sv_min = -3.2, sv_max = 3.2: the limits of the steering velocity (rad/s)
  • tau_steer = 0.15779476: the time constant of the servo (s). The servo follows its command as a first-order lag.

Command limiter (the actuation_manager of ForzaETH, in ForzaETH/f1tenth_system, with the limits of NUC5 from the race stack, stack_master/config/NUC5/vesc.yaml)

  • command_rate = 75.0: how frequently the limiter sends a command (Hz)
  • steer_cmd_min = -0.3271441202, steer_cmd_max = 0.2917771883: the range of the steering command (rad)
  • steer_rate = 2.4615384615: the maximum rate of change of the steering command (rad/s)
  • speed_cmd_min = -14.375, speed_cmd_max = 14.375: the range of the speed command (m/s)
  • accel_cmd = 2.5, decel_cmd = 2.5: the maximum rates at which the speed command increases and decreases (m/s²)

Motor controller (a VESC with the speed control of its firmware, as vedderb/bldc does it). ForzaETH do not publish their VESC settings. Thus all these values, but not erpm_gain, come from one published VESC configuration of an F1TENTH car: vesc1_apr9 (vesc/config/vesc1_apr9/vesc_mcconf.xml in TeoIlie/F1TENTH_System). It is the only published configuration for the standard F1TENTH motor (the motor of the standard f1tenth_original configuration, detected again), on firmware that can run the commands of ForzaETH: braking in speed control, and up to 100,000 ERPM. Its speed loop uses the default values of the firmware, but not for the derivative filter.

  • erpm_gain = 4800.0: the electrical RPM of the motor for each m/s (race stack, vesc.yaml of NUC5, speed_to_erpm_gain)
  • erpm_ramp = 25000.0: the maximum rate of change of the speed setpoint (ERPM/s)
  • vesc_kp = 0.004, vesc_ki = 0.004, vesc_kd = 0.0001, vesc_kd_filter = 0.5: the gains and the derivative filter of the speed PID
  • vesc_min_erpm = 900.0: below this setpoint (ERPM), the speed loop stops and the firmware holds the duty cycle at zero. This shorts the windings.
  • vesc_rate = 1000.0: the rate of the speed loop (Hz)
  • current_max = 65.0: the motor current limit (A)
  • flux_linkage = 0.000755263, motor_resistance = 0.006, motor_inductance = 8.6e-7: the flux linkage (Wb), the winding resistance (Ω) and the winding inductance (H) of the motor, as the motor detection of the VESC measured them

LiDAR (the Hokuyo UST-10LX, which the standard F1TENTH stack operates with urg_node; Hokuyo specification C-42-04077)

  • scan_rate = 40.0: the scans each second (25 ms for each revolution at 2400 rpm). The car sees the latest scan until the next scan.
  • scan_noise = 0.03: the standard deviation of the range noise (m). This is the repeatability limit in the datasheet, σ < 30 mm (white target, factory conditions). It is the only value that the datasheet gives.
  • scan_range = 10.0: the detection range (m). The specification gives 0.06 to 10 m on white Kent sheet (0.06 to 4 m at 10 % diffuse reflectance; for dark walls, set 4.0; 30 m maximum). A beam that finds no wall in this range reads 65.533 m. A beam that finds a wall nearer than 21 mm reads 0.004 m. These are the error outputs in the specification (65533 and 4, in mm). Only the valid distances get noise.
  • lidar_x = 0.27: the distance of the LiDAR in front of the rear axle (m) (race stack, static_transforms.yaml of NUC5, from base_link (the center of the rear axle) to laser). The default lidar_dist of the environment (measured from the center of gravity) is lidar_x - lr.

Resistance (off: there are no published identified values for an F1TENTH car. To use them, measure them with a coast-down test of your car.)

  • C_roll = 0.0: the rolling resistance coefficient (force C_roll * m * g)
  • CdA = 0.0: the drag coefficient multiplied by the frontal area (m²; force ½ ρ CdA v²)

Body size, for collisions and for the window

  • width = 0.228 (m): race stack, car_model.yaml of NUC5 (width_m)
  • length = 0.58 (m): the default of the f1tenth_gym fork of ForzaETH. The configuration of NUC5 gives no length.

A dict (with String or Symbol keys) must have all the keys. The function ignores other keys.

Dynamics

F1Tenth.vehicle_dynamics_st — Function
vehicle_dynamics_st(x, u_init, params::VehicleParams) -> SVector{7}

The dynamic single-track model, with Magic Formula tires, a friction ellipse and a 4WD drivetrain with an open differential.

  • The state is x = (x, y, steering angle, velocity, yaw, yaw rate, slip angle).
  • The input is u_init = (steering velocity, drive acceleration). The function clips the steering velocity to the steering limits. The drive acceleration is the force of the motor divided by the mass, before the tires limit it.
  • Below 0.5 m/s, the function uses the kinematic model.

The lateral force on each axle is mu * D * Fz * sin(C * atan(B*α - E*(B*α - atan(B*α)))), multiplied by sqrt(1 - (Fx/Fmax)^2) for the grip that the drive force Fx uses. The body accelerations are the single-track model of ForzaETH (in their EKF and in their f1tenth_gym fork), with the front drive force added:

v̇x = (Fxr + Fxf cos δ - Fyf sin δ - Fres) / m + vy ψ̇
v̇y = (Fyr + Fxf sin δ + Fyf cos δ) / m - vx ψ̇
ψ̈  = (lf (Fyf cos δ + Fxf sin δ) - lr Fyr) / I

where Fres is the rolling resistance plus the aerodynamic drag. For the sources of the parameters, see VehicleParams.

F1Tenth.drive_force_per_amp — Function
drive_force_per_amp(params) -> Float64

The drive force on the car for each amp of motor current (N/A). A permanent-magnet motor with field-oriented control makes the torque 1.5 * pole_pairs * flux_linkage * current. Through the gearing, the force multiplied by the car speed is equal to the torque multiplied by the motor speed. The electrical speed of the motor for each m/s is erpm_gain * 2π/60. Thus the pole pairs cancel, and the force for each amp is 1.5 * flux_linkage * erpm_gain * 2π/60. The model has no drivetrain losses.

F1Tenth.actuate! — Function
actuate!(car::RaceCar, steer, speed)

Move car forward by one time step with the planner command (steer, speed):

  • The command limiter ticks at command_rate.
  • The VESC speed loop and the steering servo run at vesc_rate.
  • The integrator of the car integrates the vehicle model over each of these sub-steps.
  • After each sub-step, the function compares the body with the walls (F1Tenth.body_hits_wall). After a hit, the car stops where it is, keeps its heading and stays there for the remaining part of the step.
  • The LiDAR sweeps start on the same sub-steps. The function records the pose of the car during each sweep.

Performance settings

F1Tenth.TRACER — Constant
F1Tenth.TRACER[] = :auto | :simd | :scalar

The LiDAR tracer. The two tracers give identical scans. :auto (the default) selects the faster one for this CPU when you use it for the first time.

source
F1Tenth.THREAD_AGENTS — Constant
F1Tenth.THREAD_AGENTS[] = true | false

If true (the default) and Julia has more than one thread, each car steps on its own thread. If you run many simulators in parallel yourself, set it to false.
